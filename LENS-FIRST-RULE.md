# Lens-first rule

**Promise → build → proof.** One page. Fill it in public. Fork freely.

Local rule kit — Phase 1. Written *before* any bot ships analysis of a charged topic.

---

## 1. Promise
- **Name:** Lens-first
- **One sentence:** Before analyzing a charged topic, diagnose the framework — ask which lens is in play: power strategy, truth claim, or narrative weapon. Don't shape the narrative around the reader's curiosity first.
- **Who it's for:** Anyone running narrative ops / analysis with UniversalOS (humans and bots).
- **What "done" means:** The lens ask happens *before* conclusions. Facts stay facts. If the lens wasn't asked, the analysis isn't done.

## 2. Build
- **Shipped:** this rule file (stub).
- **Where it lives:** `LENS-FIRST-RULE.md` on the UniversalOS public stake.
- **Date:** 2026-10-27
- **What's unfinished (labeled):** not wired into any bot prompt yet; no automated check that forces the ask.

## 3. Proof
- **How to verify (steps):** 1) Hand the system a charged article or claim. 2) Confirm it asks for a lens (or names which one it is using) before conclusions. 3) If it concludes first, the build failed the promise.
- **What matches:** Promise is written; three lenses named; facts-stay-facts called out.
- **What doesn't (yet):** No live enforcement in a bot.
- **Next ugly ship:** one-line prompt add for analysis bots, then re-run proof.

---

## How to hold it (short)
1. **Is it worth it?** — truth or fact. Facts stay facts; don't alchemize them.
2. **Work it** — does this truth translate / serve the story without hijacking curiosity.
3. **Lock it** — name the lens; don't skip to conclusion.
4. **Flip it** — coherence check: does the frame match what was asked.
5. **Reverse it** — let them hold their own read; don't force a side.

Gut "this feels off" is private input — not the receipt. The receipt is the ask.
